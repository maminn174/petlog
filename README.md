# Petlog

Petlog — backend-приложение для совместного ухода за домашними животными.
Владелец ведёт историю кормлений, прогулок, измерений веса и заметок, а также
приглашает других пользователей к уходу за питомцем с разными правами доступа.

Учебный pet-проект на Java и Spring Boot. В репозитории находится REST API без
пользовательского интерфейса. Проект развивается; текущая версия предназначена
для локального запуска.

## Возможности

- Регистрация, вход и выход. Авторизация через HTTP-сессию и cookie `JSESSIONID`.
- Создание питомцев и просмотр доступных пользователю питомцев.
- Совместный доступ с ролями `OWNER`, `MEMBER` и `VIEWER`.
- Приглашения зарегистрированных пользователей, принятие и отклонение приглашений.
- Управление участниками: изменение роли и удаление участника владельцем.
- История событий с пагинацией: кормление, вес, заметка и завершённая прогулка.
- Изменение событий с проверкой прав: владельцем или участником — автором события.
- Мягкое удаление событий: запись сохраняется в БД, но исключается из выдачи.
- Валидация запросов и единый формат ошибок API.

## Устройство проекта

Код сгруппирован по предметным областям. Контроллеры принимают HTTP-запросы,
сервисы выполняют бизнес-логику и проверки доступа, репозитории работают с БД.
DTO используются для запросов и ответов API.

```text
src/main/java/com/petlog/
├── auth/         # Регистрация, сессии и настройки безопасности
├── user/         # Пользователи
├── pet/          # Питомцы
├── petmember/    # Участники и роли
├── invitation/   # Приглашения к совместному уходу
├── events/       # События, история и валидация
└── common/       # Общая обработка ошибок
src/main/resources/db/migration/  # Версионируемые SQL-миграции Flyway
src/test/java/com/petlog/         # Тесты сервисов, валидации и веб-слоя
```

Основные таблицы: `users`, `pets`, `pet_members`, `events`, `pet_invitations`.
Связь пользователя с питомцем и роль хранятся в `pet_members`. Данные, зависящие
от типа события, хранятся в поле `events.data` типа JSONB.
Flyway создаёт и обновляет схему; Hibernate проверяет её через `ddl-auto: validate`.

## Локальный запуск

### Требования

- JDK 21 и настроенная переменная `JAVA_HOME`.
- Docker с запущенным движком и Docker Compose v2, поддерживающий `up --wait`.
- Свободные порты `8080` для приложения и `5434` для PostgreSQL.
- Доступ в интернет при первой загрузке Maven, зависимостей и Docker-образа.

Maven отдельно устанавливать не нужно: в репозитории есть Wrapper.
Приложение запускается на компьютере, PostgreSQL — в контейнере.

### 1. Клонировать репозиторий

```shell
git clone https://github.com/maminn174/petlog.git
cd petlog
```

### 2. Подготовить настройки

PowerShell:

```powershell
Copy-Item .env.example .env
```

Linux / macOS:

```shell
cp .env.example .env
```

Откройте `.env` и задайте собственный непустой `DB_PASSWORD`.
Для этого локального файла используйте пароль из латинских букв и цифр без
кавычек: файл читается и Docker Compose, и Spring Boot в формате Java properties.
Не используйте пароль от реальной БД или другого сервиса. `.env` исключён из Git.

| Переменная | Значение по умолчанию | Назначение |
| --- | --- | --- |
| `DB_HOST` | `localhost` | Адрес БД для приложения |
| `DB_PORT` | `5434` | Порт БД на компьютере |
| `DB_NAME` | `petlog` | Имя БД |
| `DB_USER` | `petlog` | Пользователь БД |
| `DB_PASSWORD` | Нет; обязательна | Пароль БД |

Приложение читает `.env` из текущего рабочего каталога, поэтому команды нужно
выполнять из корня проекта. При запуске из IntelliJ IDEA задайте корень проекта
как Working directory. Переменные окружения могут переопределять значения файла.

### 3. Запустить PostgreSQL

```shell
docker compose up -d --wait
docker compose ps
```

Compose запускает БД и ждёт успешного healthcheck. PostgreSQL доступен только
локально на `127.0.0.1:5434`. Если порт занят существующей БД, измените `DB_PORT`
в `.env` перед запуском. Данные сохраняются в Docker volume `postgres_data`.

### 4. Запустить приложение

PowerShell:

```powershell
.\mvnw.cmd spring-boot:run
```

Linux / macOS:

```shell
sh ./mvnw spring-boot:run
```

При старте Flyway применит миграции автоматически. Дождитесь сообщения
`Started PetlogApplication` в логах. Адрес API: `http://localhost:8080/api`.
Главная страница и Swagger UI не предусмотрены; защищённые запросы требуют входа.
Тестовые пользователи и питомцы автоматически не создаются.

### Остановка и повторный запуск

Остановите приложение через `Ctrl+C`, затем выполните:

```shell
docker compose down
```

Эта команда сохраняет данные БД. Для повторного запуска выполните шаги 3 и 4.
Переменные `DB_NAME`, `DB_USER` и `DB_PASSWORD` инициализируют PostgreSQL только
при первом запуске с пустым volume. Их изменение в `.env` не меняет существующую
БД: для неё нужно отдельно обновить пользователя и пароль. Удаление volume
стирает данные, поэтому не используйте его для смены пароля нужной БД.

## Текущее состояние и планы

В проекте есть тесты бизнес-логики, проверки прав, валидации и обработки ошибок.
Автоматическая проверка в CI пока не настроена.

Ближайшие направления развития:

- Завершить сценарий начала и окончания прогулки с активным состоянием.
- Добавить документацию API и примеры запросов.
- Настроить автоматическую сборку и запуск тестов.
- Разработать интерфейс приложения.

Перед размещением приложения в интернете потребуется отдельная подготовка
настроек безопасности, включая CSRF-защиту для авторизации через сессии.
